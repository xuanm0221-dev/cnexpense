# F&F CHINA 비용 대시보드

FP&A 관점의 월별 비용 데이터를 시각화하는 인터랙티브 대시보드입니다.

## 🎯 주요 기능

- 📊 **4개 사업부 비용 모니터링**: MLB, KIDS, DISCOVERY, 경영지원
- 📅 **당월/YTD 전환**: 단월 또는 누적 데이터 즉시 전환
- 📈 **YoY 분석**: 전년 대비 증감률 및 증감액 자동 계산
- 🏷️ **대분류별 집계**: 직접비/영업비 탭으로 세분화된 비용 분석
- 🔄 **동적 데이터 로딩**: 월별 CSV 추가 시 자동 반영

## 🚀 시작하기

### 1. 의존성 설치

```bash
# Node.js 의존성
npm install

# Python 의존성 (전처리용)
pip install -r scripts/requirements.txt
```

### 2. 데이터 준비

비용 CSV 파일들을 `비용파일/` 폴더에 배치합니다:

```
비용파일/
├── 24.01.csv
├── 24.02.csv
├── ...
└── 25.12.csv
```

**CSV 파일 형식**:
- 파일명: `YY.MM.csv` (예: `24.01.csv`)
- 필수 컬럼:
  - 코스트 센터
  - 금액(전표 통화)
  - 전표 유형
  - G/L 계정
  - G/L 계정 설명
  - 텍스트

### 3. 데이터 전처리

```bash
python scripts\preprocess.py
```

이 스크립트는:
- 월별 CSV 파일을 자동으로 로드
- 코스트센터 및 계정과목 마스터와 조인
- 사업부별/비용구분별/대분류별로 집계
- `data/processed/aggregated-costs.json` 생성

### 4. 개발 서버 실행

```bash
npm run dev
```

브라우저에서 [http://localhost:3000](http://localhost:3000) 접속

### 집계 — 관리식 / 재무식 두 기준

헤더의 **`관리식 | 재무식`** 탭으로 전환합니다 (기본: 관리식).

| | 관리식 (기본) | 재무식 |
|---|---|---|
| 그룹 | [연월, 사업부, **영업비/직접비**, 대분류] | [연월, 사업부, **연결계정과목**] |
| 직접비/영업비 | 구분함 (탭으로 전환) | **구분 없음** (탭 숨김) |
| 분류 기준 | `계정과목마스터.csv` 의 대분류 | `계정과목맵핑.csv` 의 `연결계정과목` |
| 카테고리 | 급여·복리비·광고비·수수료… (15종) | 인건비·광고선전비·수수료·감가상각비·기타 (5종) |
| 급여/복리 중분류 펼침 | O | X (관리식 대분류 기준 지표) |
| 인당 복리비 | O | X (복리비가 '기타'에 포함) |

- `계정과목맵핑.csv`: `sap code`(= 비용파일의 G/L 계정) → `연결계정과목`(재무제표에서 합쳐 쓰는 기준)

#### 포함 여부는 맵핑 CSV의 `관리` / `재무` 컬럼으로 결정
값이 **`사용`** 인 계정만 해당 기준에 집계합니다 (`X` 또는 공란이면 제외).

| 제외 대상 | sap code | 계정명 |
|---|---|---|
| **관리식 제외** (`관리`=X) | 61350101 / 62010101 | 잡이익_보조금 · 금융비용_수수료 |
| **재무식 제외** (`재무`=X) | 96030101 / 96030103 / 96030105 | 관리회계_판매수수료 · 임차료(조정) · 플랫폼수수료(조정) |
| | 41010112 / 41010113 / 41010114 | 대리상지원금 (리베이트 · 인테리어지원 · 온라인광고지원금) |
| | 43010108 / 43030108 | 제품·상품매출원가_대리상보조금 |

⚠️ 두 기준의 포함 계정이 다르므로 **총액이 서로 다릅니다.**

##### 관리식 `대리상지원금` 대분류 = 8개 계정
`55240103 / 55240105 / 55240107 / 41010112 / 41010113 / 41010114 / 43010108 / 43030108`
— **코스트센터 유무와 무관하게 전부 포함**합니다. 코스트센터가 브랜드를 주지 못하는
4로 시작하는 계정은 아래 순서로 사업부를 정합니다.

| 계정 | 코스트센터 | 브랜드 판단 |
|---|---|---|
| 43010108 / 43030108 | `CNF00000`(Common) | **장부 `자재` 첫 글자** — `I`=MLB KIDS, `M`=MLB, `X`=Discovery |
| 41010112/13/14 | 공란 | `자재` 가 비어 있어 **`사업 영역 내역`** 으로 배정 |
| 55240103 | `CNFM0100`/`CNFI0100` | 코스트센터 그대로 |

직접비/영업비는 코스트센터(`CNF00000`=영업)가 아니라 **계정 마스터의 `직접/영업`** 을 따르므로
8개 계정 모두 **직접비**입니다 (`aggregate_data()`).
- 맵핑 CSV에 없는 G/L 계정도 재무식에서 제외됩니다 (전처리 로그에 금액이 출력됨).
- 표시 순서: 인건비 → 광고선전비 → 수수료 → 감가상각비 → 기타 (`FINANCIAL_CATEGORY_ORDER`)
- **합계**: 금액(전표 통화)

> 맵핑 파일을 갱신하면 `data/masters/계정과목맵핑.csv` 로 복사한 뒤
> `python scripts/preprocess.py --full` 을 실행해야 반영됩니다.

### IFRS 조정분개 (재무식 전용)

장부(SAP G/L)를 IFRS로 전환하는 **수기 조정분개**를 재무식에만 더합니다. 관리식은 장부 그대로입니다.

- 파일: `D:/로컬파일/비용대시보드파일/조정분개/YY.MM.xlsx` (분기말 기준), 시트 `调整分录`
- 사용 컬럼: **C = pkg code**, **G = P&L 차변**, **H = P&L 대변** → **비용 = 차변 − 대변** (CNY)
  - E/F(Balance sheet)는 사용하지 않습니다.
- **pkg code가 맵핑에 있는 계정만** 반영 → 영업이익 아래 계정(이자비용·법인세·처분손익·잡손익)과
  매출(410100)은 자동으로 빠집니다. 대시보드가 영업이익까지만 보기 때문입니다.
- **분기 누적 → 증분 변환**: 파일 금액은 그 시점까지의 누적이므로 직전 분기와 차분해 분기말 월에 넣습니다.

  | 저장 월 | 넣는 값 |
  |---|---|
  | 3월 | `YY.03` (1Q 누적) |
  | 6월 | `YY.06 − YY.03` |
  | 9월 | `YY.09 − YY.06` |
  | 12월 | `YY.12 − YY.09` |

  이래야 `2분기 = YTD(6월) − YTD(3월)` 과 YTD·당월이 모두 맞습니다.
- 조정분개에 브랜드 구분이 없어 **전액 `MLB` 사업부에 귀속**합니다
  (`ADJUSTMENT_BUSINESS_UNIT`). 사업부 구분 규칙 자체는 관리식과 동일합니다.
- 상세 페이지 계정 상세표에서 **`[IFRS 조정분개]`** 라벨로 펼쳐 볼 수 있습니다.
- ⚠️ 조정분개 파일을 추가·수정하면 **`--full` 로 재실행**하세요. 증분 모드는 이번에 처리한
  월의 조정만 반영합니다 (미반영 월은 로그에 표시).

## 💱 환율 (CNY → KRW)

재무식을 선택하면 헤더에 **`CNY | KRW`** 전환 탭과 **`환율표`** 버튼이 나타납니다.
(관리식에서는 항상 위안 기준)

### 적용 규칙 — 비용 대시보드이므로 **평균환율** 사용
| 뷰 모드 | 사용 컬럼 | 예 (2026년) |
|---|---|---|
| 당월 | **월평균** | 2월 → 209.73 |
| 누적(YTD) | **기간평균** | 2월 → 209.37 (1~2월 누적) |
| 분기 | **누적 차감** (아래 참고) | 1분기 → 3월 기간평균 211.61 |

### 분기 (1~4분기)
분기는 **누적 차감**으로 계산합니다. 분기 전용 환율을 따로 쓰지 않습니다.

```
1분기 = YTD(3월)
2분기 = YTD(6월) − YTD(3월)
3분기 = YTD(9월) − YTD(6월)
4분기 = YTD(12월) − YTD(9월)

2분기 KRW = YTD(6월)CNY × 기간평균(6월) − YTD(3월)CNY × 기간평균(3월)
```

이렇게 해야 **분기 합계 = 연간 누적**이 정확히 맞습니다.
검증(2025년): 분기합 200,109M = YTD(12월) 200,109M ✅

- 인원수는 분기도 **평균**입니다 (분기 3개월 평균).
- 해당 분기에 비용 데이터가 없으면 탭이 비활성화됩니다 (예: 2026년 2~4분기).
- 구현: [lib/period.ts](lib/period.ts)

- `월말` 컬럼은 표에만 두고 환산에는 쓰지 않습니다.
- **YoY는 각 기간의 환율로 환산한 뒤 비교**합니다 (당기=당기 환율, 전년=전년 환율).
  그래서 원화 기준 YoY는 위안 기준과 다릅니다. 예: 2026-02 법인 비용 YOY — CNY 122% / KRW 129%
- 표시 단위: 위안 = 천위안(K), 원화 = **백만원(M)**. 인당 지표만 원화도 천원(K).
- 해당 월 환율이 비어 있으면 금액은 `—`, 헤더에 "환율 미입력" 경고가 뜹니다.

### 환율 입력 (로컬 전용)
- `환율표` 버튼 → 연도별 [월말·월평균·기간평균] × 1~12월, **소수점 2자리**까지 입력
- 저장하면 [data/masters/환율.json](data/masters/환율.json) 에 기록됩니다 → **git commit/push 해야 배포에 반영**
- 2025년 전체 + 2026년 1~6월은 입력되어 있고, 2026년 7월부터 직접 입력하면 됩니다
- 표는 **2025년부터** 표시합니다 (26년 기준 YoY만 보면 되므로 2024년은 제외).
  비용 데이터에 새 연도(2027년 등)가 생기면 컬럼이 자동으로 추가됩니다

⚠️ **배포 환경에서는 수정 불가**: `/api/exchange-rates` PUT 은 프로덕션에서 403을 반환하고,
화면의 환율표도 읽기 전용으로 렌더링됩니다.

### 금액 단위
- **내부 계산**: 위안 (CNY)
- **화면 표시**: 천위안 (K)
  - 예: 21,600,000 CNY → 21,600K

### 인원수 기준 (금액과 다름)
인원수는 **스톡(잔량)** 이라 누적 합이 의미가 없습니다.
- **당월**: 선택한 월의 인원 (2월 → 2월 인원)
- **누적(YTD)**: 1월~선택월 중 **데이터가 있는 월의 평균**
- 헬퍼: `headcountBasis(series, month, isYTD)` / `calculateYTDAverage` ([lib/calculations.ts](lib/calculations.ts))

'인당' 지표도 같은 분모를 씁니다.
- 인당 인건비(YTD) = **누적 급여 ÷ 평균 인원**
- 인당 복리비(YTD) = **누적 복리비 ÷ 평균 인원**
- YoY는 전년 동월(당월) / 전년 동기간 평균(YTD)과 비교

### YoY 계산
- **증감률**: `Math.round((현재 - 전년) / |전년| * 100)` (소수점 없음)
- **증감액**: `Math.round((현재 - 전년) / 1000)` (K 단위)
- **표시 예**: `YoY 93% (-1,540K)`

## 📈 리테일 매출 (비용률 분모)

`(mei)리테일` 스킬 §10 (RetailKpiCard / retail-kpi) 정의를 그대로 따릅니다.
구현: [app/api/retail-sales/route.ts](app/api/retail-sales/route.ts)

### 출처 및 조인 규칙
| 테이블 | 용도 |
|--------|------|
| `FNF.CHN.DW_SALE` | 매출 raw (`sale_amt` = 실판 V+, `tag_amt` = Tag가) |
| `FNF.CHN.MST_SHOP_ALL` | Online / Offline 분류 (`anlys_onoff_cls_nm`) |
| `FNF.CHN.DW_SHOP_WH_DETAIL` | 대리상 / 직영 분류 (`fr_or_cls`) |

⚠️ `DW_SHOP_WH_DETAIL`은 `SHOP_ID`가 중복 가능하므로 **`shop_fr` CTE
(`MAX(fr_or_cls) GROUP BY shop_id`)로 먼저 중복을 제거**한 뒤 조인합니다.
직접 조인하면 매출이 N배로 부풀려집니다.

### 5채널 분류
`직영(OFF)` / `직영(ON)` / `대리상(OFF)` / `대리상(ON)` / `미지정`
- `COALESCE(fr_or_cls, '') != 'FR'` → 직영 (NULL 매장도 직영으로 집계)
- `anlys_onoff_cls_nm IS NULL` → `미지정` (4채널 정의 밖이지만 합계에 포함)
- **정합성**: 4채널 합 + 미지정 = 브랜드 단순 합계

### 사업부 매핑
| brd_cd | 사업부 |
|--------|--------|
| M | MLB |
| I | MLB KIDS |
| X | Discovery |
| V | Duvetica |
| W | SUPRA |

- **법인** = 위 5개 브랜드 합산
- **경영지원** = 자체 브랜드 매출이 없으므로 **법인 값을 그대로 사용** (API가 직접 내려줌)

### 기간
당월(해당 월 1일~말일)과 누적(YTD, 1/1~해당 월 말일)을 당년·전년 모두
**한 번의 쿼리·한 번의 API 호출**로 집계합니다.

### 정합성 검증
```bash
node scripts/verify-retail.js 2025-12
```
브랜드별 `4채널 합 + 미지정 = 단순 SUM(sale_amt)` 를 확인하고,
`DW_SALE`에 존재하지만 매핑되지 않은 `brd_cd`를 함께 출력합니다.
